# Стартовый пакет проекта «Догяндекс: Мокрый Нос»

Этот пакет содержит исходные условия и пустые шаблоны для проекта «Догяндекс: Мокрый Нос».

## Как пройти пакет

Прочитайте файлы по порядку:

1. `00-case-brief.md` — продуктовая легенда и вопрос решения.
2. `01-data-and-quality-constraints.md` — границы функции, качества, данных и риска.
3. `02-economics-inputs.md` — выданные экономические входы, их статус и правила расчёта.
4. `03-economics-analysis.template.md` — пустой каркас экономического анализа.
5. `04-market-gtm.template.md` — пустой каркас исследования и первого GTM-теста.
6. `05-decision-summary.template.md` — пустой каркас итогового решения.
7. `06-rubric.md` — критерии проверки всего результата.

После чтения создайте отдельную рабочую папку. Скопируйте в неё три шаблона и переименуйте копии:

| Шаблон из пакета | Новый файл в рабочей папке |
|---|---|
| `03-economics-analysis.template.md` | `economics-analysis.md` |
| `04-market-gtm.template.md` | `market-gtm.md` |
| `05-decision-summary.template.md` | `decision-summary.md` |

Работайте только в новых файлах. Не изменяйте стартовый пакет.

Все конструкции в фигурных скобках, например `{ваш вывод}`, — нейтральные плейсхолдеры. Замените их собственным проверенным содержанием. Плейсхолдер не является фактом, подсказкой к вердикту или готовым ответом.

## Что сдавать

Обязательный комплект состоит из пяти частей:

1. `economics-analysis.md`.
2. `market-gtm.md`.
3. `decision-summary.md` со следом применения ИИ.
4. Презентация ровно на 5 смысловых слайдов.

Три Markdown-файла передаются как файлы. Презентацию передайте файлом или ссылкой в ридми.

Пять слайдов выполняют фиксированные функции:

1. **Проблема, пользователь и сильная альтернатива без ИИ:** текущий процесс, узкое место, пользователь, buyer и причина сравнивать ИИ с формой и правилами.
2. **Функция, граница автоматизации и качество:** путь `заявка → ИИ-черновик → диспетчер → подтверждение`, граница функции, риск-флаги, критическая ошибка и human approval.
3. **Экономика и ключевая чувствительность:** сценарии, определяющее допущение, результат расчёта и условие пересмотра.
4. **Рынок, позиционирование и первый GTM-тест:** сегмент, buyer, проверенные факты и неизвестные, канал, сообщение, метрика и порог.
5. **Внедрение, governance и решение:** роли и доступы, инцидент и откат, выбранный итог, следующий тест и сигнал пересмотра.

## Как использовать ИИ

ИИ можно использовать для:

* декомпозиции исследовательского вопроса;
* формулирования гипотез;
* критики расчёта и решения;
* поиска противоречий;
* структуры документов, слайдов.

Ответ ИИ не является источником, проверенным расчётом или готовым решением. Существенные тезисы нужно проверить по первоисточникам, а формулы — пересчитать. В `decision-summary.md` сохраните минимум одну существенную итерацию по цепочке:

`задача → контекст → результат ИИ → собственная проверка → решение`
